# DARNA Admin — Heuristic & IHM Compliance Matrix (Conformité au Cours ENP)

This document provides a comprehensive audit and traceability matrix demonstrating how the DARNA Admin Console satisfies every Human-Computer Interaction (IHM) law, psychological theorem, and architectural guideline taught in the university course *Concepts de base d'IHM* (ENP, Dr. O. Arki, 2020/2021).

## 2. Page-by-Page Micro-Checklist Compliance (§6)

Every list page and detail page across the DARNA Admin Console satisfies the 10-point micro-checklist:

| Checklist Criterion | Implementation Details | Verified Pages |
|---|---|---|
| **1. Title + One-Line Description + Breadcrumbs** | Clear page header with human title and plain-language subtitle; clickable breadcrumb hierarchy back to Home. | Home, Approvals, Hosts, Guests, Listings, Bookings, Money, Reviews, Onboarding, Settings |
| **2. ONE Obvious Primary Action** | Exactly one dominant solid primary button per page (e.g., "Add host", "Export CSV", "Approve all verified"). | All list pages |
| **3. $\le 4$ Inline Filters + "More Filters"** | Primary inline filters limited to Search, Type, Wilaya, and Status. Additional filters tucked into "More filters" modal. Active filters shown as removable chips with "Clear all". | Hosts, Listings, Bookings, Guests |
| **4. $\le 7$ Default Table Columns** | Tables default to $\le 7$ columns. First column is human name/entity (never an obscure ID). | Hosts (6 cols), Listings (6 cols), Bookings (6 cols), Guests (5 cols) |
| **5. Row Action = Primary + "⋯" Menu** | One instant primary button per row (e.g. "Review", "Inspect", "Recharge") + "⋯" dropdown for secondary/destructive actions. | All data tables |
| **6. Helpful Empty / Loading / Error States** | No blank screens. Skeletons appear during load; empty states explain why there are no items and offer a button to proceed. | All list views |
| **7. Help "?" Drawer Present & Accurate** | Top header features `?` button opening contextual help with page purpose, common tasks, glossary, and shortcuts. | Global header (all pages) |
| **8. Reachable in $\le 3$ Clicks from Home** | Direct links from 7-item sidebar or dashboard task cards. Verified $\le 3$ clicks for all 14 jobs. | All pages |
| **9. Responsive & RTL (en/fr/ar)** | Fluid layouts at 375px, 768px, 1280px; full layout mirroring in Arabic. | All pages |
| **10. Glossary Compliance (No Banned Jargon)** | All labels, table columns, and status pills strictly sourced from `lib/glossary.ts` and verified i18n files. | Global codebase |

## 3. Host Detail Page Tab Reduction (Miller Compliance)

Per §2 and §6 of the addendum, the Host detail page tabs were reduced from 11 cluttered tabs to **exactly 6 cohesive tabs**:

```
Previous Cluttered Architecture (11 tabs - Cognitive Overload):
[Overview] [Documents] [Listings] [Rooms] [Trips] [Vehicles] [Bookings] [Team] [Notes] [Money] [Audit Log]

New Miller 7±2 Compliant Architecture (6 tabs):
1. Overview    ← Includes summary, staff team, and internal moderator notes
2. Documents   ← Identity card, commercial registry, and tourism license
3. Listings    ← Unified catalog; rooms, trips, vehicles, and stays organized as sub-sections
4. Bookings    ← Reservations, guest stays, and check-in timeline
5. Money       ← Wallet balance, recharge ledger, commission tier, and payouts
6. History     ← Audit log of actions, status changes, and staff decisions
```
