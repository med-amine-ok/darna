# Traceability matrix: requirement to rule, table, API, test and milestone

> **In plain words**
> One line per requirement (all 147 from [requirements.csv](requirements.csv)).
> Each line says which business rules it follows, which database tables hold its data, which API calls serve it,
> where its tests will live, in which roadmap milestone it is built, and which app data module stops using demo data.
> Use it to answer "if we change X, what else moves?" and "is everything planned somewhere?".
> This page and [traceability.csv](traceability.csv) are generated by `python _tools/build_traceability.py`. Edit the script, not the tables.

**Terms used here** (see [glossary.md](glossary.md)):
- **Traceability**: being able to follow one need from the request, through the rules and the database, to the test that proves it.
- **Milestone**: a block of build work with an exit test, defined in [11-roadmap.md](11-roadmap.md).
- **API area**: the family of web addresses (endpoints) the apps call. Final paths are in `06-api-design.md` and `openapi.yaml` (tagged with `x-requirements`); names here are plain REST guesses.
- **job:** a scheduled background task (Celery). **internal:** a service called by other code, with no public address.
- **`lib/data` module**: the file in the website (`web:`) or admin (`admin:`) app whose functions switch from demo data to the API, behind a per-module flag.
