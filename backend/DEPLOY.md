# Deploying the BLADUS backend on Render

The repository root has a `render.yaml` Blueprint. It creates, in Render's
**Ohio** region (next to the Neon database in us-east-2):

| Render service | What it is |
|---|---|
| `bladus-backend` | The Django API (gunicorn), `https://<name>.onrender.com/api/v1/`, health check `/api/v1/health` |
| `bladus-redis` | Key Value (Redis): shared rate limits, login lockouts, SMS budget |
| `bladus-outbox` | Cron, every minute: `run_outbox` |
| `bladus-bookings-jobs` | Cron, every 5 min: `expire_requests` then `complete_stays` |
| `bladus-moderation-sync` | Cron, every 15 min: `sync_moderation_cases` |
| `bladus-reviews-hourly` | Cron, hourly: `publish_reviews` |
| `bladus-nightly` | Cron, 01:00 UTC: `reconcile_balances` (fails on a ledger difference) then `publish_reviews --recompute` |
| `bladus-monthly-invoices` | Cron, 1st of the month: `monthly_invoices` |

Each deploy: `pip install` + `collectstatic` (build), `migrate` (before the new
version starts, using `DATABASE_DIRECT_URL`), then gunicorn. A failed migration
stops the deploy and the old version keeps running.

## 1. Before the first deploy

1. Push this repository to GitHub (`main`).
2. Rotate the Neon password (Neon > Roles > Reset password) and use only the
   new connection strings on Render. The old ones lived in a local `.env`.
3. Make the Fernet key for `INTEGRATION_KEYS` (encrypts hotel system passwords
   and authenticator secrets). Keep a copy in your password manager: losing it
   makes those secrets unreadable.

   ```bash
   python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
   ```

4. Choose the mailbox that sends the emails (password reset links, email
   confirmation links, team invitations). Sign-up itself sends no email.

   **Your own mailbox over SMTP.** Any mailbox you own can send the
   codes: the `bladus.dz` mailbox from your domain host, or a Gmail account.
   Render blocks SMTP ports on **free** web services (since 2025-09-26); a paid
   instance (Starter) can use ports 587 and 465. Port 25 is always blocked.

   | Variable | Gmail | Mailbox of your domain host |
   |---|---|---|
   | `EMAIL_HOST` | `smtp.gmail.com` | the SMTP server your host gives (for example `mail.bladus.dz`) |
   | `EMAIL_PORT` | `587` | `587` (or `465`, SSL is then switched on by itself) |
   | `EMAIL_HOST_USER` | the Gmail address | the full mailbox address |
   | `EMAIL_HOST_PASSWORD` | an app password (Google account > Security > 2-Step Verification > App passwords) | the mailbox password |
   | `DEFAULT_FROM_EMAIL` | `BLADUS <the same Gmail address>` | `BLADUS <no-reply@bladus.dz>` (the same mailbox) |

   Gmail sends at most about 500 emails a day and may mark mail from a new
   sender as spam; a mailbox on your own domain with SPF and DKIM records set
   at your domain host is delivered better. Then check with `send_test_email`
   (section 4).

## 2. Create the services

1. Render > **New > Blueprint** > connect GitHub > pick the `darna` repository.
2. Render reads `render.yaml` and asks for every value marked `sync: false`:

| Variable | Value |
|---|---|
| `INTEGRATION_KEYS` | The Fernet key from step 1.3 |
| `DJANGO_ALLOWED_HOSTS` | `api.bladus.dz,.onrender.com` |
| `CORS_ALLOWED_ORIGINS` | `https://bladus.dz,https://admin.bladus.dz` |
| `CSRF_TRUSTED_ORIGINS` | `https://api.bladus.dz` |
| `FRONTEND_URL` | `https://bladus.dz` |
| `DATABASE_URL` | Neon **pooled** connection string (host has `-pooler`) |
| `DATABASE_DIRECT_URL` | Neon **direct** connection string (same host without `-pooler`) |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google Cloud Console > Clients |
| `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` | Your mailbox (step 1.4) |
| `DEFAULT_FROM_EMAIL` | An address the mailbox may send from, for example `BLADUS <no-reply@bladus.dz>` |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` | Twilio Console > Account info (phone codes by SMS) |
| `TWILIO_MESSAGING_SERVICE_SID` or `TWILIO_FROM` | Twilio Messaging Service (MG...), or a Twilio number / approved sender name |

   To use Infobip instead, set `SMS_BACKEND=apps.accounts.sms.InfobipSmsBackend`
   with `INFOBIP_BASE_URL`, `INFOBIP_API_KEY` and `INFOBIP_SENDER`. Without a
   real SMS provider nobody can verify a phone (codes would only reach the logs).

   `DJANGO_SECRET_KEY` and `HASH_PEPPER` are generated by Render. Never change
   `HASH_PEPPER` afterwards: it would sign everybody out and void every code.

3. Click **Apply**. The first build takes a few minutes; watch the logs of
   `bladus-backend`. It is ready when `/api/v1/health` answers `{"status": "ok"}`.

## 3. Domain

1. `bladus-backend` > Settings > Custom Domains > add `api.bladus.dz`.
2. At your domain registrar, create the DNS record Render shows (a CNAME to
   `<name>.onrender.com`). Render issues the HTTPS certificate itself.
3. In Google Cloud Console, keep `https://bladus.dz/api/auth/google/callback`
   in the authorised redirect URIs (the website hosts the callback).

## 4. After the first deploy

- **Check email** (password reset depends on it): `bladus-backend` > Shell >
  `python manage.py send_test_email you@example.com`. It prints the backend and
  sender in use, then "Sent" or the exact error (wrong password, sender address not
  verified, SMTP port blocked).

- **Demo data** (staging only, never on a database with real users):
  `bladus-backend` > Shell > `python manage.py seed_demo --force`.
- **First admin**: Shell > `python manage.py createsuperuser`, then sign in on
  the admin panel. The staff authenticator step is off (`STAFF_MFA_REQUIRED=False`);
  turn it on before real staff use the admin.
- **Swagger**: `https://api.bladus.dz/swagger/`.

## 5. The website and the admin panel

They are separate Next.js apps (not in this Blueprint). Host them on Render web
services or Vercel with:

| App | Variables |
|---|---|
| Website (`frontend/`) | `BACKEND_API_URL=https://api.bladus.dz/api/v1`, `NEXT_PUBLIC_SITE_URL=https://bladus.dz`, `DARNA_SESSION_SECRET` (32+ random characters), `BFF_PROXY_SECRET` |
| Admin (`admin/`) | `BACKEND_API_URL=https://api.bladus.dz/api/v1`, `NEXT_PUBLIC_FRONTEND_URL=https://bladus.dz` (links to the website), `BFF_PROXY_SECRET` |

**`BFF_PROXY_SECRET`: the same random value on the backend (Render), the
website and the admin (Vercel).** Visitors never call the backend directly,
so without it every visitor looks like the Vercel server and the per IP limits
(one-time codes, sign-in lockouts, request rates) apply to the whole site at once.
With it, the website passes each visitor's address and the backend believes it
only when the secret matches. Make one with
`python -c "import secrets; print(secrets.token_urlsafe(32))"`.

## Turned off for the first release

- **File uploads** (`MEDIA_UPLOADS_ENABLED=False`): photos are added by web
  address. To turn uploads on, add S3-compatible storage (for example
  Cloudflare R2: `MEDIA_STORAGE_BACKEND=s3` and the `MEDIA_S3_*` variables in
  `.env.example`) and a real virus scanner (`MEDIA_SCANNER`); the server
  refuses to start with uploads on and either one missing.
- **Online payment and payouts** (DEC-019): off in the code.
- **Staff authenticator step** (`STAFF_MFA_REQUIRED=False`).

## Settings worth knowing

| Variable | Default | Meaning |
|---|---|---|
| `TRUSTED_PROXY_HOPS` | `1` on Render | Proxies that append to X-Forwarded-For (rate limits per real IP) |
| `SECURE_HSTS_SECONDS` | `86400` | Raise to `31536000` (one year) once everything runs on HTTPS |
| `DATABASE_CONN_MAX_AGE` | `60` | Seconds a database connection is reused |
| `LOG_LEVEL` | `INFO` | Logs go to Render's log stream |

## Costs (check Render's pricing page)

The web service and cron jobs need paid instances (Starter); the free Key
Value plan is enough to start. Cron jobs are billed for the minutes they run;
`bladus-outbox` runs every minute and is the main cost among them. Neon's free
plan suspends the database when idle (the first request then takes a second or two).
